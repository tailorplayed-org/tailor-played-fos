02

הנחות היסוד

FOS היא מערכת ההפעלה הפיננסית של שני העסקים של בן — TailorPlayed (משחקי לוח מותאמים) ו-Benefits (קורס AI). בקצרה: "ה-RiseUp של העצמאות של בן". V2 היא שכתוב מאושר.

היררכיית האמת

חבילת התכנון docs/v2/ היא מקור האמת היחיד. בכל התנגשות היא גוברת על ארטיפקטי V1 שב-_bmad-output/ — V1 הוא היסטוריה ורקע, לא דרישות.

חמשת הכללים — "Governing rules (non-negotiable)"

  1. בונים נכון מהפעם הראשונה. לא build-then-fix.
  2. שום דבר לא כותב את אוצר המילים החדש של הקטגוריות ל-Firestore לפני שמיגרציית אוצר המילים (Gap 1) הושלמה. המלכודת: WO_FIELD_MAP ב-functions/src/triggers/onTransactionApproved.ts:9-13 תולה את צבירת הזמנות העבודה (rollups) על מחרוזות קטגוריה, ומת בשקט על מחרוזת לא מוכרת.
  3. בכל התנגשות — docs/v2/ גובר על ארטיפקטי V1 ב-_bmad-output/.
  4. לא ממציאים נתונים פיננסיים. אף פעם.
  5. משמעת סקופ — פריטים ב-Parked נשארים מחוץ ל-V2.

04

תשעת הפערים על ארבעת הגלים

סדר האפיקים המומלץ הוא סדר הגלים. מסמך האפיקים הוא זה שקובע את המספור הסופי — כאן הצעת הסדר והסיבות לה.

Wave 1 (foundations):  Gap 1 ← Gap 2 (parallel) ← Gap 9 (parallel, anytime)
Wave 2 (schema):       Gap 3 ← Gap 4 (deliver goes live at its end — the email loop closes)
Wave 3 (real data):    Gap 5 ← Gap 6 (FOS becomes a true single source of truth)
Wave 4 (experience):   Gap 7 ← Gap 8 (FOS becomes the approved RiseUp-of-the-business)

חוק הסדר: "build it right — nothing writes the new vocabulary before Gap 1 lands." כל גל הוא בעל ערך בפני עצמו.

BMad Loopכן — בשלושה תנאים

אחרי שהתנאים מתקיימים, זה המנוע לטחינה הארוכה: (1) PowerShell 7 מותקן ו-bmad-loop validate ירוק; (2) [verify] commands מאוכלס; (3) sprint-status של V2 נזרע.

השערים per-epic כבר מוגדרים נכון. כשהלופ עוצר על escalation ברמת CRITICAL ← /bmad-loop-resolve <story-key>.

הערה: bmad-loop-sweep הוא לאוטומציה בלבד — הוא מסרב לרוץ מחוץ לסשן sweep של הלופ. העבודה הנדחית מצטברת ב-deferred-work.md, ו-bmad-loop sweep עושה לה טריאז'.

03הטיית האשרור ב-brownfield

bmad-architecture במצב brownfield מנחה לאשרר את הקונבנציות הקיימות במקום להמציא חדשות. אלא שהקונבנציות של קוד V1 כוללות בדיוק את אנום הקטגוריות הנידון להריסה.

האנטידוט: project-context.md — שנכתב על ידי bmad-generate-project-context אל _bmad-output/project-context.md ונטען אוטומטית כמעט בכל סקיל — חייב לומר במפורש שאוצר המילים הלגסי ב-src/ מיועד להריסה ב-Gap 1, ואסור לאשרר אותו כקונבנציה.

"ratify the conventions already there rather than invent new ones"
04דילוג שקט על done, וחוק ה-wedge

כלל השימור לא מוריד סטטוס קיים: מפתח סטורי מתנגש יישאר done ולא יידחף לעולם. במקביל, סטורי blocked תוקע את הלופ כולו.

שתי המסקנות: (א) מארכבים את sprint-status.yaml הישן ואת 32 קבצי הסטורי; (ב) בונים את האפיקים כך שעבודה שהלופ לא יכול לשלוח — Gap 4 בריפו חיצוני, Gap 8 שאינו קוד — תשב באפיקים נפרדים ש-bmad-loop run רגיל לא מגיע אליהם, ומשתמשים ב-bmad-loop run --epic <N> לסקופינג.

"a `done` entry is skipped (never re-dispatch done)"
05מציאות ה-scm ו-verify ריק

isolation = "none" אומר שהלופ עורך ישירות בעץ העבודה שלך, בלי ענפים, ובלי גלגול לאחור בכשל. branch_per = "story" נכנס לתוקף רק במצב worktree. ובמקביל [verify] commands = [] אומר ששער האיכות הדטרמיניסטי היחיד של הלופ ריק כרגע.

עריכות יום 0: לאכלס את verify ב-npm run build, npm run lint, npm test (ואת הבדיקות של חבילת functions באותו מנגנון), ולעבור ל-isolation = "worktree" — לפני הריצה האוטונומית הראשונה על ריפו פיננסי.

[scm] isolation = "none" rollback_on_failure = false [verify] commands = []
