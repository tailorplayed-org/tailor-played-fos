# TP-FOS Email Structure Specification

## מטרת המסמך

מסמך זה מתאר את מבנה המיילים שנקבע עבור TailorPlayed, כדי שמערכת TP-FOS תדע כיצד לנתב, לתייג ולעבד מיילים נכנסים.

-----

## עקרונות החלוקה

### הפרדה חשבונאית

החלוקה מבוססת על הפרדה בין שני סוגי הוצאות:

|סוג     |הגדרה                                                |תיבה ראשית   |
|--------|-----------------------------------------------------|-------------|
|**COGS**|עלויות ישירות למוצר - הוצאות שניתן לייחס למשחק ספציפי|`orders@`    |
|**OPEX**|הוצאות תפעוליות - תשתיות, SaaS, הוצאות כלליות        |`developing@`|

### כלל ההחלטה

> “האם אני יכול לרשום את ההוצאה הזו על Work Order של משחק ספציפי?”
> 
> **כן** → orders@ / supplies@
> **לא** → developing@ / expenses@

## זרימת המידע (Data Flow) - לסגירה מול TP-FOS

### תהליך 1: הוצאה נכנסת (Expense Fork)

```
מייל נכנס מספק
       │
       ▼
┌─────────────────────────────────────┐
│  זיהוי: האם זו חשבונית/קבלה?       │
│  (לפי: שולח / נושא / קובץ מצורף)   │
└─────────────────────────────────────┘
       │
       ▼
┌─────────────────────────────────────┐
│            פיצול (Fork)             │
├─────────────────┬───────────────────┤
│   עותק 1        │     עותק 2        │
│   ▼             │     ▼             │
│  Paperless      │   TP-FOS          │
│  (רו"ח)         │   (ניתוח AI)      │
└─────────────────┴───────────────────┘
```

**לסגור:**

- איך מזהים שמייל הוא חשבונית?
- לאיזו כתובת Paperless מעבירים?
- איך שולחים ל-TP-FOS (Webhook? API? Forward?)

-----

### תהליך 2: הכנסה (Revenue Sync)

```
התראה מ-Stripe/Sumit
       │
       ▼
┌─────────────────────────────────────┐
│  זיהוי: תשלום נכנס מלקוח           │
└─────────────────────────────────────┘
       │
       ▼
┌─────────────────────────────────────┐
│  TP-FOS: עדכון Work Order           │
│  - זיהוי לקוח                       │
│  - עדכון שורת Revenue               │
└─────────────────────────────────────┘
```

**לסגור:**

- איך מזהים את הלקוח מתוך המייל?
- איך מקשרים ל-Work Order הנכון?

-----

### תהליך 3: רכישת חומרים (Supplies Tracking)

```
מייל מ-Game Crafter / AliExpress
       │
       ▼
┌─────────────────────────────────────┐
│  זיהוי: הזמנה / משלוח / חשבונית    │
└─────────────────────────────────────┘
       │
       ▼
┌─────────────────────────────────────┐
│  TP-FOS: עדכון Inventory            │
│  - פריטים שנרכשו                    │
│  - עלות ליחידה                      │
│  - סטטוס משלוח                      │
└─────────────────────────────────────┘
       │
       ▼
┌─────────────────────────────────────┐
│  Fork ל-Paperless (אם חשבונית)      │
└─────────────────────────────────────┘
```

**לסגור:**

- איך מפענחים את פרטי ההזמנה?
- האם Gemini AI מעבד את זה?
- איך מעדכנים מלאי?
